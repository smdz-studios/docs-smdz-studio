# 🧩 **OVERVIEW:**

- 📌 **Resource Name:** `smdz_advanced_rcs`
- 💻 **Author:** SMDZ Studios
- 🧭 **Framework:** ESX / QBCore / Qbox / Standalone (via SMDZ Bridge; the installation system requires compatible garage ownership)
- 🧾 **Version:** `1.0.0`
- ✅ **Status:** <span class="badge badge--warning">EARLY RELEASE</span>



**Short description:**

Advanced RCS is a physics-based vehicle propulsion system for FiveM, featuring **air stabilization, propelled jumps, surface adhesion, and ground acceleration**. Its optional per-vehicle installation and upgrade system adds a mechanic workflow, a customizable tablet, durability, payments, and persistent progression.

---


# ⭐ **FEATURES:**

- 🚀 **Air Stabilization:** Activate mid-air stabilization with **G**; wheel thrusters help level the vehicle before an assisted landing.
- ⬆️ **Propelled Jump:** Launch a compatible vehicle upwards with **J**, with a controlled return to the ground.
- 🧲 **Surface Adhesion:** Brake against a sufficiently steep surface to engage grip, then drive along walls or ceilings using the normal driving controls.
- ⚡ **Ground Boost:** Press **B** at low speed for progressive exhaust-powered acceleration, with configurable target speed and duration.
- 🔄 **360° Air Rolls:** Unlock height-dependent, optional automatic side rolls; an additional upgrade unlocks manual rolls using **X**. Obstacle and clearance checks apply.
- 🌳 **10-Module Skill Tree:** Purchase Air Stabilization, Propulsion Duration, Propelled Jump, Surface Adhesion, RCS Acceleration, Boost Speed, Advanced Cooling, Reinforced Chassis, 360° Air Roll, and Manual 360° Air Roll. Modules have configurable costs, levels, and prerequisites.
- 🔧 **Mechanic Installation:** Authorized mechanics install `advanced_rcs_kit` at configured workshops. Includes vehicle selection, repair animation, an optional `ox_lib` skill check, and cancelable progress. Bonnet opening is cosmetic and never required for installation.
- 📱 **Owner Tablet:** Use `advanced_rcs_tablet` to view installed modules, purchase upgrades, repair durability, choose cash/bank payments, change theme, and customize the wallpaper.
- 💾 **SQL Persistence:** Hardware, upgrade levels, durability, repair cooldowns, and tablet preferences survive vehicle despawns and server restarts, tied to the registered plate/model or player identity as appropriate.
- 🛡️ **Server Validation:** Checks garage ownership, driver identity, installation zones, mechanic jobs, inventory, payment, cooldowns, durability, and vehicle state.
- 💨 **Synchronized Visuals:** Adaptive wheel vapor, exhaust boost effects, white touchdown smoke, subtle landing camera feedback, and a discreet in-flight gas countdown.
- 🌐 **10 Languages:** English (default), Spanish, European Portuguese, Brazilian Portuguese, German, French, Polish, Simplified Chinese, Japanese, and Korean.
- 🔔 **Bridge Integrations:** SMDZ Bridge provides required notification, framework, inventory, and payment integrations where applicable. Optional, configurable Discord webhook logs are server-side.

These are the actual dependencies and supported integrations for Advanced RCS.

- **Framework:** ESX / QBCore / Qbox through `smdz_bridge`, or standalone driving features when the persistent installation system is disabled.
- **Dependencies (framework / database / extras):**
  - `smdz_bridge` — **required**; configure its relevant providers before starting Advanced RCS.

  - `ox_lib` — **optional**; enables mechanic skill checks and its progress UI. Installation still works without it through the fallback progress flow.

# 📥 **INSTALLATION:**

Follow these steps on a development server before moving to production.

1. Download the Advanced RCS resource archive (v1.0.0). Extract the included `smdz_advanced_rcs` folder into your FiveM resources directory. Remove any previous `smdz_wallride` physics controller to avoid conflicts.

2. Keep the folder name **exactly** as shown:

```text
resources/[smdz]/smdz_advanced_rcs
```

3. Enable OneSync and start the dependencies before Advanced RCS in `server.cfg`:

```bash
## SMDZ Studios
set onesync on
ensure ox_lib
ensure oxmysql
ensure smdz_bridge
ensure smdz_advanced_rcs
```

   `ox_lib` is optional: omit its line if you do not use mechanic skill checks. Configure and start your framework, garage, and inventory resources according to their own installation instructions.

4. With the installation system enabled by default, verify that your framework's garage table correctly identifies the car owner. Set `Config.System.Garage` to `auto`, `qb`, or `esx`. The resource can create its SQL tables automatically; if necessary, import `INSTALL_FILES/database.sql` manually.

5. Register **both** usable items from `INSTALL_FILES/items/ox_inventory_items.lua`: `advanced_rcs_kit` and `advanced_rcs_tablet`. For `ox_inventory`, copy the item entries into its item registry, preserve `consume = 0` and the `client.export` fields, then restart `ox_inventory` **before** restarting Advanced RCS. For other supported inventories, use the SMDZ Bridge inventory registration path. Do not register the same ox item twice.

6. Restart the server, or start the resource manually after its dependencies:

```bash
start smdz_advanced_rcs
```

7. Check the startup banner and server console for OneSync, bridge/provider, and SQL errors. Test an installation, tablet purchase, J/G/B controls, cooldowns, and particle synchronization with two clients before public deployment.

# 🎮 **USAGE:**

Mechanics install the hardware, owners manage upgrades and repairs, and drivers use unlocked abilities in eligible installed vehicles. The hardware alone does **not** unlock modules; all ten upgrades begin at level zero.

### Commands

| Command | Description | Permission / Notes |
|---------------------|----------------------------------------------|---------------------------------|
| `/rcsinstall [owner ID]` | Installs base RCS hardware in the selected owner's registered vehicle. | Staff only; server ACE (`smdz_advanced_rcs.install`) and/or configured framework group. The owner must be online, alive, and driving their own registered vehicle. |
| `+smdz_rcs_hover` | Key-mapping action for airborne stabilization. | Driver only; bound to **G** by default, requires the module when installations are enabled. |
| `+smdz_rcs_jump` | Key-mapping action for propelled jumping. | Driver only; bound to **J** by default. |
| `+smdz_rcs_boost` | Key-mapping action for ground acceleration. | Driver only; bound to **B** by default. |
| `+smdz_rcs_manual_flip` | Key-mapping action for a manual 360° air roll. | Driver only; bound to **X** by default, requires the upgrade when installations are enabled. |

### Keybinds

- **G** — Air Stabilization: activate while airborne; starts automatic assisted landing when the gas expires.
- **J** — Propelled Jump: launch from the ground and descend under assisted control.
- **B** — Boost: accelerate progressively while moving slowly on the ground.
- **X** — Manual Air Roll: trigger one safe 360° roll during an active RCS flight, if unlocked.
- **Brake + W/S + A/D** — Engage on a detected steep surface with the brake, then drive and steer along the wall or ceiling.
- **E** — Confirm the highlighted vehicle during mechanic installation; **Backspace/Escape** cancel selection where supported.
- **How to change:** Edit the `DefaultKey` values in `config.lua`, or rebind the registered actions in FiveM's **Settings → Key Bindings**. Existing player bindings may override new defaults.

### UI / Menus

- **Mechanic interaction:** Use `advanced_rcs_kit` near a valid car at a configured workshop; choose the vehicle, approach its front, complete the optional skill check, then finish the cancelable progress bar. The registered owner must remain nearby by default.
- **Tablet:** Use `advanced_rcs_tablet` inside or near your installed vehicle (4 m default). Open the vehicle dashboard, interactive skill tree, durability/repair page, or settings. Drag and scroll to explore the tree; purchase modules and repairs using available cash/bank accounts.
- **Visual feedback:** Wheel/exhaust thrusters, synchronized touchdown smoke, localized notices, and an optional flight-gas countdown. The countdown appears only during active airborne propulsion.

### Exports

```lua
-- CLIENT: Called by a supported inventory item or a trusted client integration.
exports['smdz_advanced_rcs']:useInstallationKit()
exports['smdz_advanced_rcs']:useTablet()

-- SERVER: Called by an authorized server-side tuning/purchase workflow.
local ownerId = source
local vehicle = GetVehiclePedIsIn(GetPlayerPed(ownerId), false)
local netId = vehicle ~= 0 and NetworkGetNetworkIdFromEntity(vehicle) or 0
local installed, reason = exports['smdz_advanced_rcs']:InstallSystem(ownerId, netId)
if not installed then
    print(('Advanced RCS installation rejected: %s'):format(tostring(reason)))
end
```

| Export name | Side | Parameters | Returns | Description |
|-------------------|---------|---------------------------|-----------------|-------------------------------------|
| `useInstallationKit` | Client | `itemData?` (table), `slot?` | `nil` | Starts the installation interaction. The supplied `ox_inventory` item definition forwards its item context for validation; server checks still apply. |
| `useTablet` | Client | `itemData?` (table), `slot?` | `nil` | Requests the owner tablet for an eligible installed vehicle. |
| `InstallSystem` | Server | `ownerId` (player server ID), `vehicleNetId` (number) | `true, nil` or `false, reasonKey` | Installs base hardware on the connected owner's garage-registered vehicle, subject to server validation. No upgrades are unlocked. |

**Important:** `InstallSystem` does **not** charge a player or remove an item. A calling tuning resource must verify its own staff access, pricing, and payment before invoking the export. Never expose it through an unprotected client-triggered network event. For `ox_inventory`, keep the two `client.export` definitions from `INSTALL_FILES/items/ox_inventory_items.lua` rather than registering duplicate item callbacks.

# 🧪 **COMMON ISSUES:**

| Issue | Recommended Solution |
| --- | --- |
| Resource does not start | Confirm the folder is named `smdz_advanced_rcs`.<br>Check that OneSync is enabled and both `oxmysql` and `smdz_bridge` start before Advanced RCS.<br>Read the startup banner for missing dependencies/providers. |
| Database errors or upgrades not saved | Verify the SQL connection and import `INSTALL_FILES/database.sql` if automatic creation fails.<br>Check for `smdz_rcs_vehicles` and `smdz_rcs_preferences`.<br>Garage owner records must match the vehicle's plate and the player's identifier. |
| Mechanic cannot install the kit | Confirm the mechanic job/grade, `advanced_rcs_kit` item, workshop radius, nearby registered owner, and selected vehicle.<br>Bonnet opening is only visual and does not block installation.<br>If `ox_lib` is absent, the optional skill check is skipped. |
| Item does nothing / invalid inventory callback | For `ox_inventory`, copy the complete provided entries, especially `client.export` and `consume = 0`.<br>Restart `ox_inventory`, then Advanced RCS.<br>Do not register duplicate item-use handlers through the bridge. |
| Ownership verification fails | Ensure your ESX/QBCore/Qbox garage table exists and stores the real owner of the exact plate.<br>Set `Config.System.Garage` correctly.<br>The installation rejects unregistered vehicles rather than assigning arbitrary nearby players as owners. |
| Vehicle abilities remain locked | Installing the hardware does not grant upgrades.<br>The owner must purchase Air Stabilization and each required branch in the tablet.<br>Check durability and remaining server-authorized cooldowns. |
| 360° roll does not happen | Unlock Air Roll (and Manual Air Roll for **X**); ensure enough altitude and unobstructed space.<br>Automatic rolls are chance-based and increase with altitude.<br>Temporarily enable `Config.Diagnostics.LogToF8` in `technical_config.lua` to review rejection reasons. |
| Admin command or permissions not working | Enable `Config.AdminInstallation`; verify `PermissionMode`, framework groups, and/or ACE `smdz_advanced_rcs.install`.<br>Example: `add_ace group.admin smdz_advanced_rcs.install allow`.<br>The command cannot be run from the server console. |
| Tablet does not open | Confirm the player owns the installed vehicle and is inside or within `Config.System.TabletUseDistance` of it.<br>Check `RequireTabletItem`, database readiness, and SMDZ Bridge providers.<br>Verify the NUI assets exist in `ui/dist`. |
| Effects behave differently between clients | Verify OneSync, test with two real clients, and check entity network ownership.<br>Vehicle models have different exhaust, wheel, and body geometry; fine-tune values in `technical_config.lua`.<br>This resource is an **early release** and requires live-server physics testing. |

# ❓ **FAQ – FREQUENTLY ASKED QUESTIONS:**

| Question | Answer |
|----------|--------|
| **What is Advanced RCS?** | Advanced RCS is a vehicle enhancement system that introduces air stabilization, propelled jumps, surface adhesion, powerful boosts, and unlockable upgrades to FiveM. |
| **Which frameworks are supported?** | Advanced RCS supports ESX, QBCore, and Qbox through SMDZ Bridge. |
| **What dependencies are required?** | SMDZ Bridge and oxmysql are required. OneSync must be enabled. ox_lib is optional and provides mechanic skill checks. |
| **Does Advanced RCS work with custom vehicles?** | Yes, compatible add-on cars can use Advanced RCS. However, some custom vehicle models may behave differently depending on their physics and configuration. |
| **Does it work with motorcycles, helicopters, or aircraft?** | No. Advanced RCS is designed for cars and does not support motorcycles, bicycles, helicopters, or aircraft. |
| **How do players install Advanced RCS?** | Players can install the system using the installation kit at a configured workshop, provided they meet the installation requirements. |
| **Can I configure installation locations?** | Yes. Workshop locations and their allowed installation distances can be customized in the configuration. |
| **Does installing the system unlock every feature?** | No. Installing the hardware provides access to the system. Individual abilities and improvements must be unlocked separately through the tablet. |
| **How do players unlock upgrades?** | Players can open the Advanced RCS tablet and purchase available modules using the configured in-game currency. |
| **Can I customize upgrade prices?** | Yes. Upgrade prices and several gameplay parameters can be adjusted through the configuration files. |
| **What happens if a vehicle is deleted or despawns?** | Installed systems and purchased upgrades are stored in the database and can be restored when the registered vehicle is loaded again. |
| **Are upgrades saved after a server restart?** | Yes. Vehicle installations, purchased upgrades, and other persistent data are stored using oxmysql. |
| **Can administrators install Advanced RCS directly?** | Yes. Authorized administrators can use the configurable installation command, subject to the configured ACE and framework permissions. |
| **Can players perform 360-degree flips?** | Yes. Automatic and manual aerial rotations are available as unlockable upgrades. |
| **Can players customize the tablet appearance?** | Yes. The tablet includes appearance settings such as light and dark themes and customizable wallpapers. |
| **Does the script support multiple languages?** | Yes. Advanced RCS includes English, Spanish, Portuguese, Brazilian Portuguese, German, French, Polish, Chinese, Japanese, and Korean. English is the default language. |
| **Is ox_lib mandatory?** | No. The resource can operate without ox_lib, but the optional mechanic skill-check functionality will be skipped. |
| **Can I change the default controls?** | Yes. Several gameplay controls and behavior settings can be customized through the resource configuration. |
| **Is Advanced RCS optimized?** | Advanced RCS uses event-driven logic and adaptive processing where possible to reduce unnecessary resource usage. Actual performance depends on the server and active features. |
| **Is the resource still under development?** | Yes. Version 1.0.0 is an early release. Some vehicle models or unusual physics situations may require further adjustments. |
| **Where can I report bugs or request support?** | Please contact SMDZ Studios through our official support channels and include any relevant error messages, screenshots, or reproduction steps. |
